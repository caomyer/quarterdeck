Why it looks like this

Two readings, one surface, two sections

Context is this conversation's headroom, updated after every turn, and it only goes wrong by being unknown. Plan limits belong to the account, move over hours and days, and go wrong by being unreadable. They share one strip so there is one place to look, and never share a number.

No "all agents" selector

Plan limits are account-wide already: the crew, the first mate and anything else signed in draw on the same windows, so a per-agent split would be invented. Context is only knowable for the first mate, whose session the app hosts. A crewmate's own context would belong on its task, not here.

Quiet until it matters

Ink at sidebar alpha until a window passes 80% or a context passes 75%, then amber; coral only at a hard limit. The strip shows the first mate's own provider always, and any other provider only once it is warning.

Missing numbers are not errors

A provider that needs sign-in shows what it needs and the one action that fixes it, in quota-axi's own words beside ours. Providers the fleet never uses fold into one line, so thirteen unconfigured tools do not read as thirteen failures.

Claude does not wait for the Keychain

The first mate's own session already reports Claude's limit status and reset time on every rate-limit event. That fills the Claude row without any prompt; Keychain access only adds the percentages.

No Detailed | Compact toggle

Orca needs one because its bar is the compact view. Here the strip is compact and the popover is detailed, and a row's chevron opens the per-window pace for anyone who wants it.
